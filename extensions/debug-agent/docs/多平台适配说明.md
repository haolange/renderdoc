# AIRD Framework · 多平台适配说明

本文档说明如何在 6 个支持的平台上部署和使用 AIRD Framework。

---

## 架构概览

```
debug-agent/
├── common/                    ← 平台无关的核心层（单一真相来源）
│   ├── AGENT_CORE.md          ← 9 个 Agent 的权威定义
│   ├── agents/                ← 9 个 Agent 的核心 Prompt（平台无关）
│   ├── invariants/            ← 知识层：23 个不变量
│   ├── taxonomy/              ← 知识层：症状/触发条件分类学
│   ├── skills/                ← 知识层：7 个 SOP
│   ├── hooks/                 ← 质量 Hook 系统（验证脚本 + Schema）
│   ├── docs/                  ← 自进化基础设施文档
│   ├── cases/                 ← 历史案例（Action Chain）
│   └── project_plugin/        ← Project Plugin 规范和示例
└── platforms/                 ← 各平台适配层
    ├── claude-code/
    ├── code-buddy/
    ├── claude-work/
    ├── copilot/
    ├── minimax/
    └── manus/
```

**核心原则：修改 Agent 逻辑 → 只改 `common/agents/` → 再同步到各平台适配层。**

## 平台一：Claude Code

### 文件结构
```
platforms/claude-code/
└── agents/
    ├── 01_team_lead.md
    ├── 02_triage_taxonomy.md
    ├── 03_capture_repro.md
    ├── 04_pass_graph_pipeline.md
    ├── 05_pixel_value_forensics.md
    ├── 06_shader_ir.md
    ├── 07_driver_device.md
    ├── 08_skeptic.md
    └── 09_report_knowledge_curator.md
```

### Frontmatter 格式
```yaml
---
name: "Agent 名称"
description: "简短描述"
model: "claude-sonnet-4-5"
tools: "bash,read,edit,glob,grep"
color: "#颜色代码"
---
```

### 特有特性：Quality Hooks（系统级强制）
`.claude/settings.json` 配置了 3 类原生 Hook：
- **PostToolUse Hook**：BugCard 写入 `kb/` 时自动运行 `bugcard_validator.py`
- **PostToolUse Hook**：Skeptic 签署文件写入时自动运行 `skeptic_signoff_checker.py`
- **Stop Hook**：Team Lead 输出「最终裁决」时自动检查反事实验证记录

### 知识文件动态加载
Agent 在 prompt 中声明加载路径，Claude Code 通过文件系统路径直接读取：
```
# 动态加载：
# - common/invariants/invariant_library.yaml
# - common/taxonomy/symptom_taxonomy.yaml
```

## 平台二：Code Buddy

### 文件结构
```
platforms/code-buddy/
├── .codebuddy-plugin/
│   └── plugin.json            ← Plugin 配置
└── agents/
    ├── 01_team_lead.md
    ├── 02_triage_taxonomy.md
    ├── ...
    └── 09_report_knowledge_curator.md
```

### Frontmatter 格式
```yaml
---
name: "Agent 名称"
description: "简短描述"
model: inherit
tools: ["read", "bash"]        # JSON 数组格式
skills: aird-debug
---
```

### 特有特性：Skills 自动加载
`.codebuddy-plugin/plugin.json` 配置了 AIRD Debug Skills，agents/ 目录下的 Markdown 文件自动作为 Skills 加载。

### 知识文件动态加载
Agent 在 prompt 中声明加载路径，Code Buddy 通过文件系统路径直接读取：
```
# 动态加载：
# - ../../common/invariants/invariant_library.yaml
# - ../../common/taxonomy/symptom_taxonomy.yaml
```

## 平台三：Claude Work

### 文件结构
```
platforms/claude-work/
├── plugin.json                ← Plugin 配置（v2.0.0）
└── agents/
    ├── team_lead.md
    ├── triage.md
    ├── capture.md
    ├── pipeline.md
    ├── forensics.md
    ├── shader.md
    ├── driver.md
    ├── skeptic.md
    └── curator.md
```

### Frontmatter 格式
```yaml
---
name: "Agent 名称"
description: "简短描述"
tools: ["read", "bash"]        # JSON 数组格式
color: "#颜色代码"
---
```

### plugin.json 关键字段
```json
{
  "version": "2.0.0",
  "core_source": "../../common/AGENT_CORE.md",
  "knowledge_base": [
    {"name": "invariant_library", "path": "../../common/invariants/invariant_library.yaml"},
    ...
  ]
}
```

### 质量 Hook：Prompt 层降级
每个 Agent 包含「质量门槛检查」清单，作为系统级 Hook 的软约束替代。

## 平台四：Copilot

### 文件结构
```
platforms/copilot/
└── agents/
    ├── 01_team_lead.md ~ 09_report_knowledge_curator.md
```

### Frontmatter 格式（与 Claude Code 相同）
```yaml
---
name: "Agent 名称"
description: "简短描述"
model: "claude-sonnet-4-5"
tools: ["bash", "read"]        # JSON 数组格式（与 Claude Code 不同）
color: "#颜色代码"
---
```

### 注意事项
- tools 字段使用 JSON 数组格式（Claude Code 使用逗号分隔字符串）
- 无原生 Hooks 支持，依赖 Prompt 层质量门槛

## 平台五：MiniMax

### 文件结构
```
platforms/minimax/expert_agents/
└── aird_all_agents.md         ← 9 个 Agent 合并为单文件（1572 行）
```

### 格式特点
- 无 frontmatter，使用 `---` 分隔各 Agent
- 每个 Agent 以 `# Agent: <名称>` 行开头
- 单文件格式适配 MiniMax 的多 Agent 合并模式

### 使用方式
将 `aird_all_agents.md` 整体加载，通过 Agent 名称标识切换到对应 Agent。

### 质量 Hook：Prompt 层降级
同 Claude Work，依赖各 Agent 内嵌的质量门槛检查清单。

## 平台六：Manus

### 文件结构
```
platforms/manus/workflows/
└── 00_debug_workflow.md       ← 8 步骤完整工作流文档
```

### 格式特点
- 工作流文档格式（非 Agent prompt 格式）
- 8 个步骤明确描述各 Agent 的职责和输入/输出
- 包含 ASCII 工作流架构图、质量关键词速查表

### 质量门禁
- Step 5（Skeptic 审查一）和 Step 8（Skeptic 审查二）作为显式质量关卡
- 工作流层面的中等强度强制（比 Prompt 层更强，比系统 Hook 层弱）

## 跨平台一致性保证

### 语义一致性验证方法
以下关键特性在全部 6 个平台均存在，可人工对照验证：

| 特性 | 验证方法 |
|------|---------|
| Skeptic 五把解剖刀 | 搜索「五把解剖刀」关键词 |
| Hypothesis Board 状态机 | 搜索「VALIDATED」和「REFUTED」 |
| 动态加载声明 | 搜索「动态加载」 |
| 质量门槛检查清单 | 搜索「质量门槛检查」 |
| BugCard Skeptic 签署要求 | 搜索「bugcard_skeptic_signed」 |

### 同步维护流程
```
1. 修改 common/agents/<agent>.md（核心层）
2. 手动同步到各平台适配层（按 platforms/ 下各平台格式规范）
3. 更新 common/AGENT_CORE.md 中对应 Agent 的核心定义
4. 验证跨平台一致性（搜索关键词）
5. 更新 plugin.json 中的相关描述（如有变化）
```
