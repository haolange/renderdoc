# RenderDoc Debug Agent 完整执行卡集合

## 概述

本目录包含6个完整独立的**Agent快速执行卡** (Execution Cards)，用于系统化调试RenderDoc捕获的渲染问题。

每个执行卡都是**自足的** (standalone) - 无需参考其他文档即可完成调试任务。

## 文件清单

### 1. nan_debug.md (NaN/Inf问题排查)
- **SOP**: SOP-NAN-01
- **行数**: 860
- **适用症状**: 白色像素、NaN传播、无限值、闪烁
- **常见根因**: normalize(0)、0/0除零、sqrt(负)、log(负)、pow(负,分数)
- **修复方案**: SafeNormalize、SafeDivide、SafeSqrt等安全函数库
- **执行时间**: 75分钟

**快速诊断**: 
- 症状：全白像素或闪烁  
- 检查：`rdx.shader.get_debug()` 查看NaN位置  
- 修复：使用SafeX()函数

---

### 2. color_debug.md (颜色失真问题排查)
- **SOP**: SOP-COLOR-01
- **行数**: 969
- **适用症状**: 颜色过暗/过亮、Gamma不对、颜色饱和度低
- **常见根因**: 双重Gamma、缺失Gamma、HDR->LDR压缩错误
- **修复方案**: 
  - 方案A: sRGB RT + Shader输出Linear
  - 方案B: 手动Gamma转换
  - 方案C: HDR + Tone Mapping
- **执行时间**: 90分钟

**快速诊断**:
- 症状：图像过暗或过亮  
- 检查：RT格式 + Shader中是否有pow()  
- 修复：删除手动gamma或改为sRGB RT

---

### 3. geo_debug.md (物体消失问题排查)
- **SOP**: SOP-GEO-01
- **行数**: 987
- **适用症状**: 物体消失、背面剔除错误、视锥体外、索引越界
- **常见根因**: 负缩放、Near>Far、View Matrix错误、背面剔除反向
- **修复方案**: MVP矩阵验证、剔除模式调整、深度范围修正
- **执行时间**: 90分钟

**快速诊断**:
- 症状：物体不可见  
- 检查：MVP矩阵的clipPos是否在[-w,w]范围  
- 修复：调整Far平面或改CullMode

---

### 4. tex_debug.md (纹理采样问题排查)
- **SOP**: SOP-TEX-01
- **行数**: 1116 (最详细)
- **适用症状**: 纹理缺失/错误、UV问题、Mipmap、模糊、拉伸
- **常见根因**: UV越界、Mipmap不完整、LOD Bias过大、未绑定
- **修复方案**: UV归一化、Mipmap链完整、LOD调整、采样器配置
- **执行时间**: 90分钟

**快速诊断**:
- 症状：纹理全黑或模糊  
- 检查：纹理是否绑定 + Mipmap链是否完整  
- 修复：绑定纹理 + 生成Mipmap + 调整Bias

---

### 5. depth_debug.md (深度问题排查)
- **SOP**: SOP-DEPTH-01
- **行数**: 873
- **适用症状**: Z-Fighting闪烁、遮挡错误、物体消失、近/远平面问题
- **常见根因**: Near/Far比过大、深度函数错误、Depth Bias不足、深度写入禁用
- **修复方案**: Near/Far范围调整、Depth Bias设置、函数修正
- **执行时间**: 90分钟

**快速诊断**:
- 症状：表面闪烁  
- 检查：Near/Far比是否>10000  
- 修复：调整范围或设置DepthBias=100

---

### 6. pipeline_debug.md (管线配置问题排查)
- **SOP**: SOP-PIPELINE-01
- **行数**: 1013
- **适用症状**: 编译失败、黑屏、混合错误、Alpha问题、同步失败
- **常见根因**: Shader编译失败、资源未绑定、混合配置错误、Resource Barrier缺失
- **修复方案**: 编译验证、资源绑定、混合设置、Barrier添加
- **执行时间**: 90分钟

**快速诊断**:
- 症状：黑屏或渲染无输出  
- 检查：Shader编译是否成功 + 资源是否绑定  
- 修复：修复编译错误 + 添加资源绑定

## 标准使用流程

### 第1步：识别症状
从以下表中找出匹配的症状标签：

| 症状 | 对应文件 |
|------|---------|
| 全白像素、闪烁 | nan_debug.md |
| 颜色过暗/过亮 | color_debug.md |
| 物体不可见 | geo_debug.md |
| 纹理问题 | tex_debug.md |
| Z-Fighting、遮挡错误 | depth_debug.md |
| 黑屏、编译失败 | pipeline_debug.md |

### 第2步：查看决策树
打开对应文件，查看**第二部分：决策树**，逐项判断进行诊断。

### 第3步：执行诊断阶段
按照**第三部分**的6-7个阶段逐步执行：
1. 快速定位 (5-10分钟)
2. 详细分析 (15-20分钟)
3. 根因分析 (20分钟)
4. 反事实验证 (15分钟)
5. 修复代码 (20分钟)
6. 验证流程 (15分钟)

### 第4步：应用修复
从**阶段5：修复代码模板**中选择合适的方案，应用到代码。

### 第5步：验证解决
按照**阶段6-7**的验证流程确认问题已解决。

### 第6步：输出报告
使用**第四部分：输出格式**的JSON模板生成诊断报告。

```
   ├─ 阶段3: 根因分析 (20分钟)
   ├─ 阶段4: 反事实验证 (15分钟)
   ├─ 阶段5: 修复代码 (20分钟)

5. 输出格式
   └─ JSON格式诊断报告模板

6. 快速参考表
   └─ 症状→根因→修复的速查表
```

## 工具覆盖

这套执行卡涉及20+个RenderDoc工具函数：

**数据获取**:
- `rdx.texture.get_data()` - 纹理/深度缓冲数据
- `rdx.texture.get_info()` - 纹理元数据
- `rdx.buffer.get_data()` - 缓冲数据
- `rdx.mesh.get_data()` - 网格数据

**调试信息**:
- `rdx.shader.get_debug()` - Shader执行跟踪
- `rdx.shader.get_source()` - Shader源代码
- `rdx.event.get_pixels()` - 像素历史

**管线状态**:
- `rdx.pipeline.get_state()` - 完整管线状态
- `rdx.pipeline.get_blend_state()` - 混合状态
- `rdx.pipeline.get_raster_state()` - 光栅化状态

**系统信息**:
- `rdx.api.get_log()` - API调用日志
- `rdx.resource.get_transitions()` - Resource Barrier转换
- `rdx.frame.take_screenshot()` - 渲染结果截图
- `rdx.frame.compare()` - 帧对比
